# US078 — ATCC Collaborator Remote Access

## 1. Context

This User Story was developed in Sprint 3. It introduces a remote access mechanism allowing Air Transport Company Collaborators (ATCC) to interact with the AISafe system from outside the main application, over a TCP network connection.

The ATCC is responsible for several core user stories — **US070** (Add Aircraft to Fleet), **US071** (Decommission Aircraft), **US072** (List Company Fleet), and **US073** (Create Flight Route) — which were previously only accessible through the local backoffice console. US078 makes all of them remotely available through a dedicated TCP client application, without any direct database access from the client side.

## 3. Functioning

### 3.1 Overview

The ATCC TCP server is a standalone process that listens on dedicated port **2225**. It shares the same PostgreSQL persistence unit as the rest of the system — the client never touches the database directly. Each incoming TCP connection is handled by a dedicated thread (`ATCCClientHandler`), allowing multiple simultaneous ATCC sessions.

Authentication is enforced at the session level: no command other than `LOGIN` is accepted before the client has successfully authenticated with valid `AIR_TRANSPORT_COMPANY_COLLABORATOR` credentials.

### 3.2 Protocol

The protocol is text-based, one command per line. Arguments are space-separated.

**Commands:**

| Command | Arguments | Description |
|---|---|---|
| `LOGIN` | `<email> <password>` | Authenticate as an ATCC Collaborator |
| `LIST_AIRPORTS` | — | List all registered airports |
| `LIST_MODELS` | — | List all registered aircraft models |
| `ADD_AIRCRAFT` | `<reg> <country> <iata> <modelId> <eco> <bus> <first> <crew>` | Add aircraft to fleet (US070) |
| `LIST_FLEET` | `<iata>` | List all aircraft of a company (US072) |
| `LIST_FLEET_MODEL` | `<iata> <modelId>` | List fleet filtered by model |
| `LIST_FLEET_MAKER` | `<iata> <maker>` | List fleet filtered by manufacturer |
| `LIST_FLEET_CAP` | `<iata> <minSeats>` | List fleet filtered by minimum capacity |
| `LIST_FLEET_AGE` | `<iata>` | List fleet ordered by age |
| `DECOMMISSION` | `<reg> <companyIata>` | Decommission an aircraft (US071) |
| `CREATE_ROUTE` | `<designator> <companyIata> <origin> <dest> REGULAR <day> <dep> <arr>` | Create regular route (US073) |
| `CREATE_ROUTE` | `<designator> <companyIata> <origin> <dest> CHARTER <date1> <time1> <date2> <time2>` | Create charter route (US073) |
| `LOGOUT` | — | End the session |

**Response tokens:**

| Token | Meaning |
|---|---|
| `OK` | Command succeeded |
| `ERROR <reason>` | Command failed with explanation |
| `END` | Terminates a multi-line response |
| `BYE` | Server acknowledges logout and closes the connection |

### 3.3 Session Lifecycle

| TCP Server Event | Behaviour |
|---|---|
| Client connects | Thread spawned, awaiting `LOGIN` |
| Authentication succeeds | Session marked authenticated; `OK Welcome <email>` sent |
| Authentication fails | `ERROR Invalid credentials` returned |
| Command before login | `ERROR Not authenticated` returned |
| Client sends `LOGOUT` | Session cleared; `BYE` sent; connection closed |
| TCP connection drops | Socket closed; thread exits |

### 3.4 Key Implementation Components

- **`ATCCServer`** — standalone process. Configures `AuthzRegistry`, registers valid email domains, bootstraps default ATCC users, and accepts TCP connections on port 2225. Each connection spawns an `ATCCClientHandler` daemon thread.
- **`ATCCClientHandler`** — implements `Runnable`. Manages one client session: parses commands, enforces authentication, delegates to existing application-layer controllers.
- **`ATCCClient`** — command-line TCP client. Connects to the server and reads user input in a loop. All commands are forwarded to the server as-is.
- **`Protocol`** — shared constants for all command and response tokens.

## 4. Integration/Demonstration

1. Start the **ATCCServer** in IntelliJ or terminal:
   ```
   mvn exec:java -pl exemplo.core -Dexec.mainClass="rcomp.ATCCServer"
   ```
2. Start the **ATCCClient** in a second terminal:
   ```
   mvn exec:java -pl exemplo.core -Dexec.mainClass="rcomp.ATCCClient" <host> 2225
   ```
3. Test authentication rejection — wrong password → `ERROR Invalid credentials`.
4. Authenticate → `LOGIN atcc@alsafe.com Atcc1234` → `OK Welcome atcc@alsafe.com`.
5. List airports → `LIST_AIRPORTS` → airport lines terminated by `END`.
6. List models → `LIST_MODELS` → model lines terminated by `END`.
7. Add aircraft → `ADD_AIRCRAFT CS-TCP Portugal TP 1 200 20 0 8` → `OK CS-TCP`.
8. List fleet → `LIST_FLEET TP` → aircraft lines terminated by `END`.
9. Filter by maker → `LIST_FLEET_MAKER TP Boeing` → filtered lines terminated by `END`.
10. Create regular route → `CREATE_ROUTE TP001 TP OPO LIS REGULAR MONDAY 14:00 15:00` → `OK TP001`.
11. Create charter route → `CREATE_ROUTE TP002 TP OPO CDG CHARTER 2026-06-15 10:00 2026-06-15 13:00` → `OK TP002`.
12. Decommission → `DECOMMISSION CS-TCP TP` → `OK CS-TCP decommissioned`.
13. Logout → `LOGOUT` → `BYE`.

## 5. Observations

- Port **2225** is dedicated to the ATCC service. The Weather Person server (US044) uses port 2226 and the Pilot server (US086) uses port 2228. All three run as independent processes on the same cloud node (`vsgate-s1.dei.isep.ipp.pt`).
- The server uses the PostgreSQL persistence unit (`eapli.base.AlSafePU.postgres`) connecting to `vsgate-s1.dei.isep.ipp.pt:10466/alsafe`. The client has no database access — all persistence is done server-side.
- The bootstrap in `ATCCServer` is idempotent — if default users already exist, the exception is caught silently.
- `ValidEmailDomains` must be registered before `AuthzRegistry.configure()` for authentication to work correctly.
- Multi-line responses (fleet lists, airport lists) are terminated by `END` so the client knows when the response is complete.
